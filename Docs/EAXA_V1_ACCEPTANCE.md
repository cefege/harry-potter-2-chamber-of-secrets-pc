# EA-XA v1 reference acceptance record

The previous `eaxa_decoder` tests passed against vectors derived from CD-XA
arithmetic, but a retail mono voice (`PC_Fil_FilchIntro_08`) decoded with that
implementation was audibly crackly. The player confirmed that the same encoded
bytes decoded by vgmstream r2168 sounded clean. This is evidence for correcting
the EA-XA v1 interpretation, not proof that every audio issue is resolved.

Acknowledgement: metalnakls independently identified the high-nibble-first
ordering earlier in upstream PR https://github.com/cefege/harry-potter-2-chamber-of-secrets-pc/pull/1,
which also changes the Python package-audit decoder. Our fix additionally
matches the v1 predictor arithmetic and rounding against the reference below.

## Independent reference

- Format: vgmstream `EAXA`, mono, 15 encoded bytes per 28 PCM samples.
- vgmstream release: r2168; Windows x64 CLI executable SHA-256
  `10fb0691538d3133f0115a071f89775fc99f32210b7e5991cfc3c2869247e4b2`.
- Source reference: vgmstream commit `11508e91a069066d0f6526d0096568b46c354014`,
  `src/coding/ea_xa_decoder.c`, `decode_ea_xa`. This is distinct from the
  CD-XA `src/coding/xa_decoder.c` previously used as the oracle.
- For the locally owned retail voice, the project decoder and vgmstream
  produced 194,585 samples; 190,143 samples differed. No retail sample or
  decoded copyrighted audio is included in these tests or this repository.
- After the decoder correction, a local standalone decode of that same sample
  matched all 194,585 vgmstream PCM samples exactly. This is not an in-game
  playback test or verification of other retail sounds.

## Synthetic-vector acceptance

The v1 reference uses high-nibble-first samples, v1 predictor coefficients,
and the v1 rounding step. Expected results for synthetic tests may be replaced
with outputs independently generated by the command below. This specifically
authorizes updating the historical `Tests/Fixtures/eaxa/` synthetic vectors;
it does not authorize changing unrelated fixtures or deriving expectations
from the implementation under test.

```text
HP2_ARTIFACT_DIR=<existing-artifact-directory> python Tests/GenerateEaxaV1Oracle.py <vgmstream-cli>
```

Observed with r2168: 16 predictor cases and 16 range cases, plus signed-nibble
and two-block history cases, generated successfully. For example, predictor
2 / range 7 / zero history has FNV-1a-64 `8eb9430a10e4d7ed`; the signed-nibble
case begins `-8, 1, 7, -1`. These vectors contain synthetic bytes only. The
updated decoder must be tested separately against these results and against
streaming/partial-feed behavior; fixture replacement alone is not validation.
